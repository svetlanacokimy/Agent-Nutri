# Как мы работаем — шпаргалка

> Этот файл — память о том, КАК мы ведём проект. Если агент потерял нить (после сжатия чата) — дай ему прочитать этот файл. «Где мы сейчас» тут НЕ хранится — это живёт в project/STATUS.md.

## Два направления (не смешиваем)
1. Движок — починка ebm_engine, миграция, обогащение.
2. Клиенты — разбор анализов и прогон через Агента.

## Где лежит память (источники правды — в файлах, не в чате)
- Движок: `project/STATUS.md`, `project/EBM_MIGRATION_STATE.md`
- Клиенты: `cases.md`
- Уроки и правила: `learning/corrections.md`
- Цифры по EBM: `scripts/ebm_audit_v2.ps1` (единственный источник)

## Волшебные фразы
- «Читай STATUS.md и EBM_MIGRATION_STATE.md» — поднять нить по движку.
- «Читай cases.md» — поднять нить по клиентам.
- «Ставим закладку по движку, переходим к клиенту» — записать в STATUS.md строку «где остановились» (с номером шага), уйти к клиентам.
- «Читай STATUS.md, продолжаем движок» — вернуться к движку с закладки.
- «Ставим закладку по клиенту, переходим к движку» — то же в обратную сторону (закладка в cases.md).
- «Закрываем день» — обновить STATUS.md (текущее состояние / последняя сессия / следующая сессия = первый шаг на завтра), затем коммит.

## Железные правила
- Файл либо переделываем целиком, либо не трогаем — никаких HYBRID.
- Перед скриптом-заменой: сначала прочитать реальную структуру файла, потом править (не по памяти).
- Правки по номерам строк с коротким маркером, не по длинной строке (консоль глотает пробелы).
- Единственный источник цифр по EBM — scripts/ebm_audit_v2.ps1. Каждая цифра в доках — со ссылкой на источник.
- Один коммит на один файл/задачу.
- В КОНЦЕ КАЖДОГО ДНЯ STATUS.md обновляется обязательно. Это не опционально.
