# EBM Workflow — рабочий процесс обогащения методичек

**Создан:** 2026-07-26 (Session 40, после прототипа covid_pregnancy.md)
**Обновлён:** 2026-07-27 (Session 48, финализация Этапа E — 8/8 методичек)
**Назначение:** пошаговая инструкция для обогащения каждой из оставшихся 7 методичек по EBM-lite (Уровень 1). Прототип отработан на `covid_pregnancy.md` — коммит `ae269dc`.

## Философия процесса

- **Скрипт делает работу, человек делает решения.** Никакой ручной вставки текста в файл.
- **Один файл = одна сессия = один скрипт = один коммит.** Не смешиваем.
- **Скрипт идемпотентен.** Повторный запуск не ломает уже обогащённый файл.
- **Бэкап всегда.** Файл `<name>.md.bak.<дата>_<время>` создаётся до правок, игнорируется git.
- **Никаких выдуманных ссылок.** Только реальные гайдлайны и RCT. Отсутствие источника помечается `[источник требуется, не проверено]`.

## Роли

**Светлана (ты):** запускаешь команды, визуально проверяешь таблицы после обогащения, принимаешь решение о коммите. Не пишешь код руками.

**Claude (я):** читаю актуальный файл с GitHub через crawler, готовлю скрипт с точными regex-паттернами, составляю список источников под конкретную тему, объясняю каждый шаг.

## Пошаговый процесс (для каждого файла)

### Шаг 1. Открытие сессии

Ты пишешь в чат: **«продолжаем EBM, следующая методичка — <имя_файла>.md»**.

### Шаг 2. Чтение актуального файла

Claude через crawler читает `https://raw.githubusercontent.com/svetlanacokimy/Agent-Nutri/copilot/build-v2-nutrition-agent-core/references/methodology/<имя>.md`.

Если файл слишком большой для crawler — Claude просит запустить:

```powershell
Get-Content references/methodology/<имя>.md -Encoding UTF8 -Raw | Set-Clipboard
```

И вставить содержимое одним сообщением в чат.

### Шаг 3. Подготовка EBM-плана

Claude формирует:

- **Список inline-замен** (15–25 штук) с точными regex-паттернами.
- **Пул источников** под тему (гайдлайны + RCT + мета-анализы).
- **Таблицу расхождений «школа vs EBM»** (8–10 пунктов).
- **Спорные зоны** — где школьная позиция не имеет EBM-подтверждения.

### Шаг 4. Создание скрипта

Ты выполняешь три команды:

```powershell
New-Item -Path scripts/ebm_enrich_<имя>.ps1 -ItemType File -Force
code scripts/ebm_enrich_<имя>.ps1
```

Затем копируешь скрипт (Claude присылает одним блоком), вставляешь в VS Code (Ctrl+V), сохраняешь (Ctrl+S).

Проверяешь размер:

```powershell
Get-Item scripts/ebm_enrich_<имя>.ps1 | Select-Object Name, Length
```

Размер должен быть в пределах 25–50 KB.

### Шаг 5. Создание бэкапа файла

```powershell
$stamp = Get-Date -Format "yyyy-MM-dd_HHmm"
Copy-Item "references/methodology/<имя>.md" "references/methodology/<имя>.md.bak.$stamp"
```

Бэкапы автоматически игнорируются `.gitignore` (паттерн `*.bak.*`).

### Шаг 6. Запуск скрипта

```powershell
powershell -ExecutionPolicy Bypass -File scripts/ebm_enrich_<имя>.ps1
```

Ожидаемый вывод:

- Блок A: список из ~20 замен со статусами `[OK]` или `[SKIP]`
- Блок B: `[OK] §XX EBM Benchmark вставлен`
- Блок C: `[OK] Метаданные обновлены`
- Блок D: `[OK] Файл записан: UTF-8 BOM, CRLF`
- Блок E: метрики валидации + `UTF-8 BOM: True`

**Критерии успеха:**

- Все замены `[OK]`, ни одного `[SKIP]` (или Claude объясняет каждый SKIP)
- Inline-ссылок `[EBM: ...]`: ≥15
- Пометок `[школа; EBM ...]`: ≥5
- `§XX EBM Benchmark присутствует: True`
- `UTF-8 BOM: True`

Ты присылаешь Claude полный вывод скрипта.

### Шаг 7. Проверка diff

```powershell
git diff --stat references/methodology/<имя>.md
```

Ожидание: одна строка `1 file changed, ~140–180 insertions(+), ~15–25 deletions(-)`.

### Шаг 8. Визуальный осмотр в VS Code

```powershell
code references/methodology/<имя>.md
```

Пробегаешь глазами:

- Таблицы, где добавлены `[EBM: ...]` — не поехали?
- Новый раздел `§XX. EBM Benchmark` (три подраздела) — читается нормально?
- Метаданные в конце — версия 1.1, статус ✅ Готов (EBM-lite), changelog?

Сообщаешь одним словом: `все ок` / `таблицы поехали` / `что-то не так`.

### Шаг 9. Коммит и push

```powershell
git add references/methodology/<имя>.md
git commit -m "feat(methodology): EBM-обогащение <имя>.md — §XX EBM Benchmark, ~20 inline-ссылок; v1.1 EBM-lite (Session <NN>, Этап E)"
git push origin copilot/build-v2-nutrition-agent-core
```

### Шаг 10. Коммит скрипта

```powershell
git add scripts/ebm_enrich_<имя>.ps1
git commit -m "chore(scripts): add ebm_enrich_<имя>.ps1 — скрипт EBM-обогащения для <имя>.md"
git push origin copilot/build-v2-nutrition-agent-core
```

### Шаг 11. Обновление EBM_UPGRADE_PLAN.md

В таблице прогресса — статус меняется на ✅, добавляется номер сессии и хеш коммита.

## Проблемы, которые уже случались (и как их обходить)

### Проблема 1. Команды слипаются при вставке в PowerShell

**Симптом:** после Ctrl+V в терминал команды объединяются в одну кривую строку типа `code file.ps1ыcode file.ps1code file.ps1`.

**Решение:** копировать и вставлять команды по одной, а не блоком. Между командами обязательно нажимать Enter в PowerShell.

### Проблема 2. VS Code создаёт пустой файл, но нам нужен файл с содержимым

**Симптом:** `code file.ps1` создаёт пустую вкладку, скрипт не появляется автоматически.

**Решение:** `code` только открывает редактор — содержимое вставляется вручную через Ctrl+V.

### Проблема 3. Файл создался под кривым именем (с кириллицей в расширении)

**Симптом:** в scripts/ появляется `ebm_enrich_....ps1ыcode` вместо чистого `.ps1`.

**Решение:** переименование через wildcard:

```powershell
Remove-Item scripts/<чистое_имя>.ps1  # удалить пустой правильный
Get-ChildItem "scripts/<имя_начало>*" | Rename-Item -NewName "<чистое_имя>.ps1"
```

### Проблема 4. Регулярка не находит фразу (SKIP в выводе)

**Причина:** в исходном тексте пробелы/дефисы/тире отличаются от того, что мы ожидали.

**Решение:** Claude берёт актуальный файл через crawler и корректирует regex-паттерн. Скрипт запускается повторно (идемпотентность защищает).

## Уроки Этапа E (Sessions 40–47)

### 1. Три формата метаданных

- Blockquote: > **Версия:** 1.0
- Plain list: - **Версия:** 2.0
- Отдельная секция ## Метаданные

Regex должен покрывать все три варианта.

### 2. Маркеры идемпотентности — обязательный паттерн

Каждый скрипт добавляет маркер вида EBM_ENRICHED_v1.1 или EBM_ENRICHED_v2.1. Повторный запуск проверяет маркер и выходит без изменений.

### 3. SKIP-замены 10–50 % — норма, не баг

Вариативность формулировок школы. Концепция покрывается через разделы EBM benchmark, таблицы расхождений, RCT. Не расширять regex — 15 точных OK лучше, чем 25 сомнительных.

### 4. Структурные аномалии — обрабатывать, не править

- nervous_system.md: дубликаты H2.
- autoimmune_basics.md строка 153: ложный H2.

Обходим regex-ами, исходник не трогаем.

### 5. Пять технических предохранителей

1. File exists check.
2. Unique anchors check.
3. Idempotency guard.
4. Order validation.
5. UTF-8 BOM + CRLF.

### 6. Реалистичный тайминг

30–50 мин на файл (не 60–90). Секрет — переиспользуемый каркас скрипта.

## Правила безопасности (одинаковые для всех файлов)

1. **Не диагностируем.** «Нутрициолог может обратить внимание», «рекомендовать консультацию врача».
2. **Тератогенные субстанции — с ⚠️ и ссылкой на источник.** Витамин А >10 000 МЕ, изотретиноин, transexamic acid, полынь, пижма, зверобой при беременности, высокие дозы селена (>400 мкг), родиола/ашваганда (спорны).
3. **Никаких брендов.** Только форма и дозировка.
4. **АБ, гормоны, тиреоидные препараты — только по назначению врача.**
5. **При явных расхождениях школа/EBM — согласовывать с профильным врачом.**

## Что запрещено

- Выдумывать ссылки → писать `[источник требуется, не проверено]`
- Использовать источники ранее 1990 (кроме исторически значимых, например MRC Vitamin Study 1991)
- Ссылаться на блоги, форумы, non-peer-reviewed материалы
- Утверждать эффективность БАД без RCT-подтверждения
- Позиционировать нутрициологию как «лечение»
