## 1. 🎯 Видение продукта

**Agent-Nutri** — это AI-помощник практикующего нутрициолога, который освобождает специалиста от ручного труда и способен к самообучению.

По результатам анализов клиента Агент генерирует:
- **EXPERT-документ** — академический разбор для специалиста (9 шагов, 10 разделов).
- **CLIENT-документ** — человеческая версия для клиента (8-13 разделов).
- **MENU** — персональное меню на основе авторских материалов нутрициолога.
- **FOLLOWUP** — сравнительный анализ «до/после» через 12 недель.

Главный пользователь — практикующий нутрициолог (не программист). Главный принцип — **доказательная медицина + авторская методология школы + личная практика** с прозрачным указанием источников.

## 2. ⚖️ Главные принципы

1. **Не ломать существующее, только дополнять.** Новые функции — отдельные команды, не трогают `/consult`.
2. **Доказательная база — основа, методология школы — слой над ней, личная практика — сверху.** Каждое назначение имеет источник.
3. **Прозрачность уровня доказательности.** Клиент и специалист видят, откуда рекомендация.
4. **Push в GitHub только после явного approve пользователя.** Никаких автоматических операций с remote.
5. **Каждый клиент — живая медкарта**, а не разовая консультация. Timeline, накопительные анализы.
6. **Сначала ядро методологии, потом инфраструктура.** Бот, web-UI, парсинг PDF — отложены.
7. **Параллельные системы допустимы в переходный период.** Старый плоский слой `references/` и новый четырёхслойный сосуществуют до завершения миграции.

**Правило для Агента (актуальное):**

При поиске информации Агент проходит четырёхслойную пирамиду сверху вниз:
1. **`clinical_guidelines/`** — международные стандарты доказательной медицины. Высший приоритет для медицинских утверждений.
2. **`methodology/`** — методология школы нутрициологии (с пометкой «методология школы XXX»).
3. **`personal_practice/`** — личный опыт нутрициолога (с пометкой «эмпирическое наблюдение»).
4. **`biochemistry/`** — фундаментальное понимание процессов; используется для объяснений «почему», не для конкретных назначений.

Если в новом слое информации ещё нет — обращение к **старому плоскому слою** (`01_*.md` ... `13_*.md`) как fallback.

В EXPERT-документе секция **«Источники рекомендаций»** указывает уровень доказательности каждого назначения.

**Концепция трёх уровней референсов** (в master-таблице `lab_values_master.md`):
- 🔵 **Лабораторный референс** — 95% условно здоровой популяции.
- 🟡 **Клинический оптимум** — диапазон минимального риска болезни по гайдлайнам.
- 🟢 **Функциональный оптимум** — диапазон максимального самочувствия (школа + функциональная медицина).

## 🧭 Как пользоваться этим файлом

**Перед каждой сессией:** прочитать раздел «План ближайших сессий» — найти текущую сессию по номеру.

**В конце каждой сессии:** обновить раздел «Текущий статус» (что сделано), добавить новое решение в Decision Log если было.

**При появлении новой большой идеи:** добавить в «Долгосрочные направления» с пометкой даты.

**При конфликте решений:** проверить Decision Log — возможно, вопрос уже решён.

**При крупных изменениях архитектуры:** увеличить версию (v2.0 → v3.0), кратко описать изменения вверху файла.
