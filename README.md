# Agent-Nutri Pro

> ИИ-агент для практикующего нутрициолога. Генерирует консультации по анализам крови в двух форматах — экспертном (для специалиста) и клиентском (для пациента) — на основе доказательной медицины и методологии российской школы нутрициологии.

**Версия:** 0.2 (в активной разработке)
**Дата последнего обновления:** 2026-05-22
**Ветка разработки:** `copilot/build-v2-nutrition-agent-core`
**Репозиторий:** https://github.com/svetlanacokimy/Agent-Nutri

---

## Зачем этот проект

Практикующий нутрициолог тратит на одну качественную консультацию по анализам крови от 3 до 8 часов: расшифровка показателей, поиск референсов, подбор нутрицевтиков, расчёт КБЖУ, оформление двух отчётов. Agent-Nutri Pro автоматизирует эту работу до 15-30 минут, сохраняя клиническую точность и индивидуальный подход.

Главный пользователь — **практикующий нутрициолог**. Любая логическая или числовая ошибка агента — это реальный риск для клиента. Поэтому проект построен на принципе **антигаллюцинации**: каждое утверждение должно быть подкреплено явным источником из доказательной базы.

## Что умеет агент

Восемь команд, описанных в `AGENT.md`:

- `/consult [Фамилия]` — полная экспертная консультация (9 разделов, дифференциальная диагностика, нутрицевтики).
- `/client [Фамилия]` — клиентская версия последней консультации (8 разделов, тёплый тон, без таблиц).
- `/compare [Фамилия]` — сравнение динамики анализов между датами.
- `/menu [Фамилия] [N]` — индивидуальное меню на N дней.
- `/intake [Фамилия]` — первичный приём, заполнение профиля клиента.
- `/links [Фамилия]` — ссылки на покупку назначенных БАД.
- `/correct [текст]` — фиксация коррекции от пользователя в `learning/corrections.md`.
- `/learn [текст]` — добавление нового знания в `learning/new_knowledge.md`.

## Архитектура (краткий обзор)

Подробное описание — в `ARCHITECTURE.md`. Здесь — краткая карта.

Проект состоит из **двух взаимосвязанных систем:**

**Операционная система** (как агент работает) — папки `v2/`, `skills/`, `learning/`, файлы `AGENT.md`, `RULES.md`, `CLAUDE.md`. Здесь живут пайплайны, правила стиля, иерархия приоритетов, накопленный опыт.

**База знаний** (на чём агент основывает выводы) — папки `references/`, `project/`, `clients/`, `text_extracted/`. Здесь живут доказательные данные, материалы школы, профили клиентов, исходные тексты уроков.

Приоритет источников при конфликте задаёт `v2/HIERARCHY.md`:
эталоны (`1expert_style_example.md.txt`, `1client_style_example.md.txt`) → `v2/` → `RULES.md` → `skills/` → `references/` → `text_extracted/`.

## Переходный период (важно понимать)

Папка `references/` сейчас содержит **два параллельных слоя**, и это сделано осознанно:

**Старый слой** — 14 плоских файлов (`01_digestion_gastro.md` ... `13_client_work.md`, `unit_conversions.md`), созданных в апреле 2026. На них опирается текущий `v2/SOURCES_INDEX.md` и работающие пайплайны.

**Новый слой** — четыре подпапки (`biochemistry/`, `clinical_guidelines/`, `methodology/`, `personal_practice/`), запущенные 22.05.2026. Здесь строится более строгая четырёхуровневая модель знаний с разделением на доказательную медицину, методологию школы и личную практику.

Миграция со старого слоя на новый — это отдельная задача в `project/ROADMAP.md`. До завершения миграции работают оба слоя; при конфликте приоритет у **нового слоя** при условии явной ссылки в `v2/SOURCES_INDEX.md`.

## Как начать работу

Этот репозиторий — не самостоятельное приложение, а структурированная база знаний и правил для работы Claude (через Claude Code, Claude Desktop или веб-интерфейс). Запуск через любую команду из `AGENT.md` в чате с Claude, у которого открыт доступ к этому репо.

Перед любой командой Claude обязательно читает файлы в следующем порядке (см. `CLAUDE.md`):
1. `v2/HIERARCHY.md`
2. `AGENT.md`
3. `learning/corrections.md`
4. `learning/patterns.md`
5. `learning/new_knowledge.md`

---

## Правила работы с репозиторием

Полный свод — в `CLAUDE.md` и `RULES.md`. Ключевые:

- **Git push** только после явного "Approve" от пользователя.
- **Эталонные файлы** (`1expert_style_example.md.txt`, `1client_style_example.md.txt`) — read-only, никогда не редактируются.
- **Имена клиентских папок** не переименовываются (Latin или Cyrillic — как заведено).
- **При конфликте правил** действует иерархия из `v2/HIERARCHY.md`; конфликт фиксируется в `learning/corrections.md`.
- **Коммиты** — на русском, формат `type(область): краткое описание` (типы: feat, fix, chore, docs, refactor).
